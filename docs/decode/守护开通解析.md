# 守护开通与升级（6540）

## 状态

历史样本确认 6540 横幅可表达开通者、开通/升级动作和守护名称。产品已通过 `TTP.addTafListener("6540")` 接入候选监听，但网页 TAF 的最终字段名和重复关系仍需真实操作复验。

## 领域合同

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `type` | 是 | 固定 `guard_open` |
| `uri` | 是 | 固定 `6540` |
| `uid` / `union_id` | 至少一个 | 用户身份；缺失则忽略 |
| `nick` | 是 | 开通者昵称 |
| `room_id` | 否 | 房间标识 |
| `banner_text` | 是 | 同时包含有效动作和已知守护名称 |
| `action` | 是 | `开通`或`升级`；`荣升`归一为升级 |
| `guard_name` | 是 | `初爱守护`、`超级守护`或`至尊守护` |

守护没有续费业务。V1～V4、开通天数和类型枚举不影响感谢，也不进入标准事件。关键字段不足时只记录文本摘要和字段键名，不发送弹幕。

## 产品规则

- 使用独立开关和模板 `感谢{nick}为主播{action}{guard_name}!`。
- 不受普通礼物金额门槛影响。
- 只接受页面 TAF 6540；WebSocket 6540 和 1400 系统句均不触发。
- TAF 解析失败时允许功能暂时不可用，不增加备用链路。

## 现场验证重点

1. 分别制造一次首次开通和升级，确认昵称、身份和横幅字段。
2. 对照同秒 6501 / 1400，确认一次操作的回调次数和去重键。
3. 验证刷新和断线重挂后监听仍正常，且不会重复感谢。
