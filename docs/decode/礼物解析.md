# 礼物（URI 6501）

## TAF 业务结构

网页官方结构为 `SendItemSubBroadcastPacket`，产品通过 `TTP.addTafListener("6501")` 订阅。

| 输出 | 官方字段 | 说明 |
| --- | --- | --- |
| `item_id` | `iItemType` | 礼物类型 |
| `order_id` | `strPayId` | 支付单号，用于去重 |
| `count` | `iItemCount` | 本包数量 |
| `sender_uid` | `lSenderUid` | 送礼用户 |
| `sender_nick` | `sSenderNick` | 送礼昵称 |
| `anchor_nick` | `sPresenterNick` | 主播昵称 |
| `item_name` | `sPropsName` | 礼物名称 |
| `room_id` | `lRoomId` | 房间号 |
| `value_fen` | `lPayTotal` | 本包合计，单位分 |

`value_yuan = value_fen / 100`。

验证期曾通过 WebSocket/JCE tag 41 对照 `lPayTotal`。该路径只保留在 `validation/docs/` 作为字段研究证据，产品不得用它补偿或替代 TAF 礼物回调。

## 筛选与去重

- `value_fen <= 0`：忽略虎粮等非现金礼物。
- `value_fen < min_value_fen`：记录低于门槛，不感谢。
- `value_fen / count < min_unit_value_fen`：记录单价低于门槛，不感谢。
- 达到门槛：进入 gift_thank。开启连击合并时，门槛在窗口结算时用合计金额和数量判断，见 [欢迎冷却与礼物合并设计.md](../欢迎冷却与礼物合并设计.md)。
- TAF 回调按 `order_id` 去重；同一用户再次购买同种礼物但订单不同，不应被压掉。连击合并是 gift_thank 的业务窗口，不能改总线去重。

守护开通是独立事件，不与礼物金额合并；只有其 TAF 订阅验证完成后才能触发感谢。
