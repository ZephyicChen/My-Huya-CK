# 小说趣味互动设计

> 状态：已实现（第一版）。与原设计的差异见文末「实现偏差」。
>
> 依赖基础：1400 弹幕识别、当前账号/白名单、LU 指令入口、统一弹幕发送队列。

## 1. 目标

在“趣味互动”分页中增加“小说”模块，把用户在本机准备好的小说文本拆成适合直播间弹幕的短段，并按配置的节奏连续发送。

模块必须满足：

- 小说发送不能长时间挤占欢迎和感谢弹幕。
- 只有当前账号和获得“小说控制”权限的白名单用户可以通过弹幕控制。
- 发送成功后才推进阅读进度，发送失败不能静默丢段。
- 进程重启后保留进度，但不能自动恢复播放。
- 小说正文不完整写入日志，也不进入 Git。

第一版不做在线书库、网页抓取、格式转换、多房间同步、多人点播和随机章节。

## 2. 用户流程

```text
打开“趣味互动”分页
  → 上传本机 UTF-8 TXT
  → 选择当前小说
  → 配置每条字数与小说间隔
  → 开启“趣味互动”和“小说”
  → 在本机点击开始，或由授权用户发送 LU 小说指令
  → 程序逐段发送并保存成功进度
  → 暂停、继续、停止或自然播完
```

上传、删除和选择小说只能通过本机 WebUI 完成，不能通过直播间弹幕操作。

## 3. 页面设计

“趣味互动”分页由三块组成。

### 3.1 趣味互动总控

- `启用趣味互动` 总开关。
- 当前状态：未启用、待机、运行中或异常。
- 总开关关闭后，所有趣味互动模块不再产生新弹幕。

远程控制本身仍没有总开关；这里的开关只限制趣味互动业务。

### 3.2 小说内容

- 上传 `.txt` 文件。
- 小说列表：名称、总字数、拆分后段数、上次进度。
- 选择当前小说。
- 显示开头预览。
- 删除小说，需要二次确认；正在播放的小说不能直接删除。
- 文件限制建议为 UTF-8、最大 5 MiB。

### 3.3 小说播放

- 小说模块独立开关。
- 每条最大字数，默认 `50`，建议范围 `20～100`。
- 小说发送间隔，默认 `10 秒`，建议最小 `3 秒`。
- 可选进度前缀，例如 `【小说 12/380】`。
- 开始、暂停、继续、停止和下一段按钮。
- 当前小说、状态、成功进度、总段数、下一段预览、最近发送结果。

小说模块有效条件：

```text
允许发送 && 趣味互动总开关 && 小说模块开关 && 已选择有效小说
```

任意条件不满足时，不产生新的小说弹幕。

## 4. 文本导入与拆分

### 4.1 导入清理

- 去除 UTF-8 BOM。
- 把 CRLF/CR 统一为 LF。
- 合并连续空格和多余空行。
- 保留自然段边界和中文标点。
- 空文件或无法按 UTF-8 解码的文件拒绝导入。

### 4.2 拆分规则

拆分顺序：

1. 优先按自然段拆分。
2. 段落过长时，优先在 `。！？；` 后切分。
3. 仍过长时，再尝试 `，、：` 等次级标点。
4. 没有合适标点时才按最大字数硬切。
5. 标点跟随前一句，不生成空白段。

如果启用进度前缀，正文可用长度为：

```text
配置最大字数 - 当前前缀长度
```

前缀使可用长度低于安全下限时，配置不能保存。

拆分结果应由“文件内容 + 拆分配置”确定。修改最大字数或前缀后重新拆分，并尽量根据原始字符偏移恢复进度，不能简单沿用旧段号。

## 5. 播放状态机

```text
idle ──开始──> playing
playing ──暂停──> paused
paused ──继续──> playing
playing/paused ──停止──> idle（进度归零）
playing ──最后一段成功──> completed
completed ──开始──> playing（从第一段开始）
任意状态 ──文件失效/配置错误──> error
```

语义固定如下：

- 开始：从第一段重新播放。
- 暂停：保留下一段位置。
- 继续：从保留位置恢复。
- 停止：停止并把进度重置为第一段。
- 下一段：请求发送当前待播段，仍遵守全局发送 CD；成功后推进一段。
- 播放完成：自动停止，不默认循环。

进程重启时，`playing` 必须恢复为 `paused`，避免无人值守时自动刷屏。

## 6. 发送与队列机制

### 6.1 优先级

统一弹幕队列需要扩展优先级：

| 优先级 | 来源 |
| --- | --- |
| 高 | 必要的指令反馈或系统告警 |
| 普通 | 欢迎、礼物、守护、超粉、贵族 |
| 低 | 小说 |

同优先级保持先进先出。高优先级不能绕过全局发送 CD。

### 6.2 单段在途

小说播放器最多只能有一段处于排队或发送状态，不能把整篇小说提前塞入队列。

```text
播放器等待小说间隔
  → 检查没有小说段在途
  → 提交一段低优先级消息
  → 等待发送结果
     ├─ 成功：保存进度，等待下一次间隔
     └─ 失败：保留当前段，进入暂停或等待有限重试
```

建议第一版发送失败后自动暂停，并在 WebUI 显示原因，由用户手动继续。这样不会在页面结构变化或登录失效时持续重试刷日志。

### 6.3 间隔

小说实际发送间隔取以下两者较大值：

```text
max(全局发送 CD, 小说发送间隔)
```

欢迎或感谢插队后，小说仍需等待自身间隔，不能为了追赶进度连续发送。

### 6.4 关闭发送

执行 `LU 关闭 发送` 或在 WebUI 关闭“允许发送”时：

- 清空统一发送队列。
- 小说状态从 `playing` 变为 `paused`。
- 保留已经成功发送的进度。
- 重新开启发送后不自动恢复小说。

## 7. LU 指令合同

第一版建议支持：

| 指令 | 行为 |
| --- | --- |
| `LU 小说 开始` | 从第一段开始播放当前小说 |
| `LU 小说 暂停` | 暂停并保留进度 |
| `LU 小说 继续` | 从保存位置继续 |
| `LU 小说 停止` | 停止并把进度归零 |
| `LU 小说 下一段` | 请求发送当前待播段 |
| `LU 小说 状态` | 返回小说名、状态和进度 |

解析规则与现有 LU 一级指令一致：

- `LU` 不区分大小写。
- 空格可以省略。
- 可以带一个结尾的 `！!。.`。
- 必须整条弹幕完整匹配，不能在普通句子中触发。

“状态”需要发送反馈弹幕，其余指令是否反馈应作为统一配置。关闭发送时不能依赖弹幕反馈确认结果。

## 8. 权限

### 8.1 当前账号

当前账号拥有完整小说控制权限。

### 8.2 白名单

现有单一 `allow_interaction` 建议演进为可扩展列表：

```json
{
  "allowed_interactions": ["novel"]
}
```

WebUI 显示“允许控制小说”勾选项。以后增加其他趣味互动功能时，继续在列表中增加独立 ID，避免一次授予全部互动权限。

兼容旧配置时，可以把 `allow_interaction: true` 迁移为空列表，并要求用户明确重新授权；安全上不应自动授予未来所有互动模块。

普通观众无论发送什么内容都不进入小说指令匹配。

## 9. 本地存储

建议新增目录：

```text
data/novels/
  index.json
  <novel-id>.txt
```

`data/` 必须加入 `.gitignore` 和发布敏感目录检查。

### 9.1 元数据

`index.json` 只保存必要元数据：

```json
{
  "novels": [
    {
      "id": "随机稳定 ID",
      "name": "小说名称",
      "file_name": "随机稳定 ID.txt",
      "size": 123456,
      "sha256": "内容摘要",
      "created_at": 0
    }
  ]
}
```

上传文件名只作为显示名称，实际文件使用程序生成的 ID，禁止把用户文件名直接拼入路径。

### 9.2 播放配置与进度

`config/app.json` 可新增：

```json
{
  "interaction": {
    "enabled": false
  },
  "novel": {
    "enabled": false,
    "novel_id": "",
    "max_chars": 50,
    "interval_ms": 10000,
    "show_progress_prefix": true,
    "next_char_offset": 0,
    "state": "paused"
  }
}
```

进度优先保存原始字符偏移，而不是只保存拆分后的段号，以便拆分设置变化后重新定位。

文件内容不放进 `app.json`。

## 10. 后端模块建议

```text
huya_ck/features/novel/
  schema.py       配置字段与默认值
  splitter.py     文本清理、拆分、字符偏移
  library.py      安全上传、索引、删除、预览
  player.py       状态机、间隔、进度和发送结果
  handler.py      LU 小说指令

huya_ck/api/novels.py
  GET    /api/novels
  POST   /api/novels
  GET    /api/novels/{id}/preview
  DELETE /api/novels/{id}
  POST   /api/novels/player/{action}
```

上传接口使用 multipart，不接受客户端提供的目标路径。删除前必须校验解析后的绝对路径仍位于 `data/novels/` 内。

`RoomWorker` 在现有 Playwright 泵循环中驱动 `NovelPlayer`。播放器不直接操作 Page，只能向统一 danmaku 队列提交低优先级消息，并接收成功/失败回调。

## 11. 日志与隐私

- 不在日志中打印完整小说段落。
- 小说日志只记录小说 ID/名称、段号、状态和最多 20～40 字预览。
- 小说正文、上传文件、播放进度和本机配置不进入版本控制。
- WebUI 运行记录可以显示当前段预览，但保持固定数量，不无限积累。
- 删除小说后删除正文和元数据；该操作不可恢复，必须二次确认。

## 12. 异常处理

| 情况 | 处理 |
| --- | --- |
| 未选择小说 | 拒绝开始，WebUI/日志说明原因 |
| 小说文件丢失或摘要不一致 | 进入 `error`，不发送 |
| 文本为空或无法解码 | 上传失败，不创建索引 |
| 登录失效或输入框不存在 | 当前段不推进，播放器暂停 |
| 全局发送关闭 | 小说暂停并清除在途段 |
| 趣味互动或小说开关关闭 | 小说暂停，不自动恢复 |
| 高优先级消息到达 | 小说让路，进度不变 |
| 小说播放完成 | 进入 `completed`，不循环 |
| 删除当前小说 | 播放中禁止；停止后才允许 |

## 13. 测试要求

### 13.1 拆分测试

- 中文标点优先切分。
- 超长无标点文本硬切。
- 前缀占用字数正确。
- 空行、BOM 和换行归一化。
- 修改字数后按字符偏移恢复进度。

### 13.2 播放器测试

- 成功后才推进进度。
- 失败时保持当前段并暂停。
- 最多一个小说段在途。
- 欢迎/感谢优先于小说。
- 全局 CD 与小说间隔共同生效。
- 重启后 `playing` 恢复为 `paused`。
- 关闭发送时暂停并清空在途段。

### 13.3 指令与权限测试

- 当前账号可执行全部小说指令。
- 有 `novel` 权限的白名单可以执行。
- 未授权白名单和普通观众不能执行。
- 普通句子包含 LU 时不误触发。
- 趣味互动或小说开关关闭时拒绝指令。

### 13.4 文件安全测试

- 拒绝非 TXT、超大文件和非法 UTF-8。
- 文件名不能实现目录穿越。
- 删除目标必须位于小说数据目录。
- `data/novels/` 不被 Git 跟踪。

## 15. 第一版验收标准

- 可以在 WebUI 上传、选择和预览 UTF-8 TXT 小说。
- 小说可以开始、暂停、继续、停止，并在完成后自动结束。
- 当前账号和获得权限的白名单可以使用六条 LU 小说指令。
- 小说发送成功后才推进，失败不会丢段。
- 连续播放时，欢迎和感谢不会被多条小说长期阻塞。
- 重启后保留进度但保持暂停。
- 普通观众不能控制小说，其正文处理边界不变。
- 小说正文不完整进入日志，不进入 Git。
- 全部单元测试、WebUI 构建和发布检查通过。

## 16. 实现偏差（2026-08-29 实现时确定）

第一版实现与原设计的差异，均为实现阶段明确的取舍：

1. **进度只记段序号**（`next_index`），不记原始字符偏移。虎牙弹幕输入框实际上限 30 字，每条字数被钉死在 15～28 的窄区间，重新拆分的场景基本消失；改字数或换书时进度归零重新开始，换取拆分器与播放器的显著简化（也消除了字符偏移追踪 bug 的温床）。
2. **无进度前缀**：弹幕只发正文，不带 `【小说 12/380】`，`show_progress_prefix` 字段保留但被忽略。
3. **每条字数默认 28、区间 15～28**（原设计 20～100、默认 50）；统一弹幕队列在入队时硬校验 28 字上限（虎牙 30 字留 2 字余量），超长拒绝入队不截断，欢迎/感谢模板同样受限。
4. **发送失败不暂停也不重试**：无论成败都推进到下一段，与欢迎/感谢“失败不重试”语义一致；播放器不代用户做暂停决定。
5. **播放器不读全局发送开关**：`LU 关闭 发送` 时由远程控制模块事件驱动暂停；WebUI 关发送则由队列拒绝入队、失败回调驱动推进。分层上小说模块只负责提交消息和记进度。
6. **`LU 小说 状态` 之外不回弹幕反馈**（维持“指令是否反馈应作为统一配置”的保守面）；状态反馈走高优先级。
7. **上传用请求体 + 查询参数名**，未用 multipart：避免引入 python-multipart 依赖。
8. 白名单按设计演进为 `allowed_interactions: ["novel"]`，旧 `allow_interaction: true` 不自动授权。
