# 新增业务事件接入流程

## 原则

生产业务只消费页面 TAF `addTafListener` 的结构化回调。WebSocket/JCE 是研发探针，用于发现和分析，不是降级通道。

```text
提出业务需求
  → WebSocket 探针发现候选 URI
  → 保存脱敏原始样本并分析结构
  → TAF 主动订阅验证
  → 定义结构化字段合同
  → 单元测试与真实场景对照
  → 注册为产品领域事件
```

任一步未完成，事件都只能留在 `validation/`，不能触发欢迎、感谢或弹幕发送。

## 1. 先定义业务事件

先说明要解决的业务动作，例如“高级用户进入”“礼物支付”“守护开通”，并列出最少字段、重复规则和触发条件。不要从某个 URI 名称倒推产品需求。

## 2. 用 WebSocket 发现候选 URI

在 `validation/` 中监听页面事件 WebSocket，记录事件信封、URI、group、时间和原始载荷。测试时同步记录人工操作时间，用于筛出与业务动作相关的候选 URI。

这一阶段允许：

- 拆 TAF/JCE 信封和观察 tag 路径。
- 保存受控、脱敏的原始样本。
- 比较多个 URI 是否同时出现。
- 发现候选表以外的新 URI。

这一阶段禁止：

- 调用产品 `bus.emit` 或功能 handler。
- 根据 WebSocket 包自动发送弹幕。
- 把 JCE tag 路径当作生产字段合同。

## 3. 验证 TAF 主动订阅

对候选 URI 使用页面 TAF 信号注册临时只读回调：

```javascript
window.TTP.ready((signal) => {
  signal.addTafListener("<uri>", (event) => {
    // 仅把结构化字段桥接到验证日志
  });
});
```

至少完成三轮真实动作，确认：

- 回调确实触发且属于目标房间。
- 字段结构在多轮中稳定。
- 是否与其它 URI 重复表示同一动作。
- 页面刷新或重挂后能重新订阅。

若 WebSocket 能看到候选 URI，但 TAF 主动订阅无法验证，则该业务暂不接入产品。

## 4. 建立字段合同

字段合同只记录 TAF 回调对象的命名字段，例如 `lUid`、`sNickName`、`lPayTotal`。WebSocket/JCE tag 映射留在验证资料中作证据，不进入产品合同。

合同至少包括：

- 用户、房间和事件身份字段。
- 金额、数量、等级等业务字段及单位。
- 必填、可选、缺失时的处理。
- 去重键和重复窗口。
- 敏感字段及日志脱敏规则。

## 5. 产品接入门槛

只有同时满足以下条件才能进入 `huya_ck/`：

- TAF 回调已在真实房间验证。
- 标准化函数有合成单元测试。
- 真实样本对照通过。
- 断线、刷新和重复回调行为已明确。
- 默认功能关闭，错误不会触发发送。
- 产品代码不导入 WebSocket/JCE 解码器。

## 7. 外部文档的使用方式

官方小程序 SDK 的字段可以帮助设计统一领域模型，但不能据此推断普通网页 TAF 对象或 JCE tag。产品仍以真实页面 `TTP.addTafListener` 回调验证为准。
